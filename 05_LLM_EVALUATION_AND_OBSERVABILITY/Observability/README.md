# Observability with LangChain and LangSmith

This lab translates the Azure workshop's tracing example into LangChain pipelines observed entirely through LangSmith.

The examples record:

- The complete question-answer trace
- A nested retrieval run
- Prompt and model runs generated by the LangChain pipeline
- Agent decisions, tool names, tool arguments, and tool results
- Inputs, outputs, latency, token usage, tags, and custom metadata
- Errors raised by any step

## Setup

```bash
cd 05_LLM_EVALUATION_AND_OBSERVABILITY/Observability
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Add your Google Gemini and LangSmith API keys to `.env`.

## Example 1: traced question-answer chain

```bash
python traced_chain.py
```

Open the project named by `LANGSMITH_PROJECT` in LangSmith. Select a trace to inspect the root application run, nested retrieval, prompt, model, parser, timing, token usage, tags, and metadata.

Try changing a question, removing relevant context, or temporarily raising an exception inside `retrieve_context` to see how different behavior appears in the trace.

## Example 2: traced tool-calling agent

```bash
python traced_agent.py
```

The agent uses two LangChain tools:

| Tool | Purpose |
|---|---|
| `get_weather` | Returns deterministic weather data for Bangkok or Tokyo |
| `get_weather_alerts` | Returns active weather alerts for a supported city |

The prompt asks Gemini to compare two cities and check alerts, so the trace contains multiple tool calls. In LangSmith, expand the `observed_weather_agent` trace to inspect:

1. The user message and agent system instructions.
2. Gemini's tool-selection response.
3. Each selected tool name and generated arguments.
4. The JSON result returned by each tool.
5. Gemini's final response grounded in those tool results.
6. Model latency, token usage, tags, metadata, and any errors.

Because the tools use a local dictionary, the example is deterministic and does not require a weather API key. Change the question to an unsupported city to observe how the agent handles a tool error in the trace.
